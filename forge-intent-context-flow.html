Forge Runtime：Intent → Context Build

自上而下閱讀；右側只畫分支與併發。

已落地部分完成旁路／離開等待
01

RECEIVE

收到原始輸入。
固定往下。

等待旁路
  • 尚未進 workflow：start_forge 後若缺知識檔，維持 RECEIVE 等明確同意。
02

INTENT_UNDERSTANDING

判斷是否啟動。
等模型最多 10 秒。

分支
  • /grill-run：跳過分類，啟動 Forge
  • 其他 slash：離開 Forge
  • 已有 workflow：拒絕雙開
  • 無 model／registry、逾時／錯誤／無效輸出：保守 start_forge
  • passthrough：離開 Forge
03

LIGHT_DISCOVERY

只找候選檔與 metadata。
完成後進 Grill。

04

GRILL

逐輪查證。
漏 completion：RECOVERY_REQUIRED，留在本狀態。

條件
completion status：READY_FOR_DEEP
  • relevance 足夠 → DEEP_KNOWLEDGE_RETRIEVAL
  • 不足 → WAIT_USER(relevance_clarification)
05

WAIT_USER

流程停住等人。
是否寫入 transcript 依觸發路徑決定。

投遞
  • 工具完成等待：多為 displayOnly
  • 命令／來源不明／relevance：可送 transcript
06

USER_CONFIRMED

接住人類回答。
依 wait kind 分流。

依 wait kind
  • grill_confirmation → Grill（同 snapshot）
  • relevance_clarification → Light → 新 snapshot → Grill
  • deep_decision → 回原 Deep phase → follow-up
  • deep_discovery_fallback：精確同意／確認 → KU＋human_premise；其他 → Wait
07

DEEP_KNOWLEDGE_RETRIEVAL

深查允許來源。
完成進 KU；需要決定則等人。

併發支線
  • PI 可平行多個 search
  • Forge call-ID barrier 等 all settled
  • 只送一次同 identity follow-up
  • 首次 needs_discovery → Light → Grill（自動 follow-up）
  • 第二次 → WAIT_USER(deep_discovery_fallback)
  • 混合 search＋completion：本批拒絕 completion
needs_decision → WAIT_USER
08

KNOWLEDGE_UNDERSTANDING

把證據固定成結論。
validator 通過進 Context。

限制
  • 空 package 仍可通過
  • human_premise 已建立；尚未送入最終 Context
  • needs_discovery：首次 → Light → Grill；第二次 → WAIT_USER(deep_discovery_fallback)
needs_decision → WAIT_USER
09

CONTEXT_BUILD

目前只有狀態切換。
production builder 尚未接入。
